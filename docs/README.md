# Meridian House Documentation

This is the reader for the Meridian House build record.

The documentation follows one principle:

> **Build the thing. Explain the thinking. Preserve the evidence.**

The project record connects:

**Client problem → insight → hypothesis → decision → architecture → implementation → evidence → learning**

## Read in this order

1. [Client](./00-client/README.md) — what the practice is, who it serves, and what the experience must accomplish.
2. [World model](./01-world-model/README.md) — how Meridian House understands cities, projects, disciplines, and its fictional institutional world.
3. [Research](./02-research/README.md) — research outputs, propositions, flagship engagements, and visitor questions.
4. [Decisions](./03-decisions/README.md) — important choices and the reasoning behind them.
5. [Information architecture](./04-information-architecture/README.md) — how content, navigation, journeys, and entities fit together.
6. [Design](./05-design/README.md) — visual, interaction, 3D, and storytelling principles.
7. [Architecture](./06-architecture/README.md) — current prototype architecture and target production architecture.
8. [Build journal](./07-build-journal/README.md) — chronological evidence of what was built and why.
9. [Security](./08-security/README.md) — security model, threat model, headers, and deployment considerations.
10. [QA](./09-qa/README.md) — testing strategy and release checklists.
11. [Handoff](./10-handoff/README.md) — deployment, maintenance, content, and future ownership.

## The governing question

A visitor should understand **how Meridian House thinks, what that thinking produces, and where their own problem enters the system.**
